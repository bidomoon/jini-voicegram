# 사진·영상 게시 안정화 — 2026-11-17

## 변경

- 영상 전송은 요청당 30초 제한과 최대 3회 재시도를 사용한다. 같은 업로드 ID·조각 번호를 유지해 응답 유실 후에도 중복 저장하지 않는다. 인증·권한·파일 오류·전송 만료·사용량 제한에는 재시도하지 않는다.
- 큰 영상 전체 조회와 구간 조회를 256KiB 단위 ReadableStream으로 반환한다. 권한과 범위 검증, private/no-store, Content-Length·Content-Range는 유지한다. 근거: Netlify 공식 Functions API 및 configuration 문서의 buffered 6MB / streamed 20MB 제한을 11월 17일 확인했다.
- 녹화 종료 때 도착한 마지막 조각도 20MB 제한을 검사한다.
- 별도 점검 공간의 작성 화면에서 공용 사진·약 7MB MP4를 넣어 기존 첨부·미리보기·분할 업로드·게시 경로를 점검할 수 있다. 자동 게시하지 않는다. 실제 피드에는 이 버튼이 없다.
- MP4는 ffmpeg로 만든 무음 2초 테스트 패턴이다. 작은 원본과 유효한 ISO BMFF free box를 조합해 정확히 7,000,000바이트를 빌드 때 만든다. 대용량 전송을 위한 패딩 파일이며 실제 사용자 촬영 영상이나 고화질 영상 시험으로 계산하지 않는다.

## 확인된 범위

전체 자동검증 61개 통과, 타입 검사 및 프로덕션 빌드 통과. 7MB 전체·구간 스트림의 원본 바이트, 스트림 취소, 응답 유실·일시적 502/503·영구 오류·응답 정지 시 제한과 재시도를 포함한다. 생성한 MP4는 ffprobe로 2초·7,000,000바이트를 확인했다.

기존 운영 화면에서는 소유자 로그인과 별도 점검 공간, 이전에 게시한 글의 재조회를 확인했다. 사진 내려받기 도중 브라우저 연결이 지연되었고 이후 연결 문맥이 없어졌다. 이 버전의 실제 브라우저 사진·영상 게시·재생과 게시글 수정, 휴대폰 마이크·카메라 검증은 아직 완료하지 않았다.
