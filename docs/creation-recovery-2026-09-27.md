# 생성 → 수정 → 게시 신뢰성 보완 (2026-09-27)

## 반영 내용

- 계정/테스트 프로필별 기기 임시 저장: IndexedDB에 글, 이미지, 직전 이미지, 생성 요청 번호, 영상 Blob을 저장. 같은 브라우저에서 새로고침 뒤 만들기로 돌아오면 복구한다. 다른 기기로 동기화되는 기능은 아니다. 저장 중/저장 완료/저장 실패를 구분해 표시한다.
- 기존 수동 임시 저장 데이터는 사용자가 불러오기를 눌렀을 때 읽을 수 있다. 로그인 리다이렉트 복구를 유지했다. 프로필이 달라지면 다른 저장 키를 사용한다.
- 생성된 그림의 ‘이 그림 수정하기’, 참조 그림 사용 여부, 사진/수채화/만화/클레이 표현을 제공한다. 표현 선택은 생성 요청에 적용되며 선택만으로 비용이 발생하지 않는다.
- 새 결과가 완성될 때까지 이전 그림을 유지한다. 실패 시 원본을 덮어쓰지 않는다. 직전 그림으로 전환하는 동작은 API 호출 없이 수행한다.
- 로컬 6초 영상은 완성 후 바로 확인 화면으로 전환하고 Blob을 보관한다. 영상 비트레이트를 3.2Mbps로 낮춰 4MB 게시 한도에 여유를 둔다. 실제 파일이 한도를 넘으면 기존 업로드 검증이 차단한다.
- 생성 요청 번호를 보낸 뒤 결과가 불확실하면 재생성하지 않고 결과 조회 버튼을 제공한다. 새 요청은 추가 비용 안내와 확인을 거친다.
- 게시 요청 번호도 초안에 저장한다. 서버 게시 성공 후 응답을 잃어 새로고침하더라도 같은 요청 번호로 재시도하므로 중복 게시를 막는다.

## 서버 처리

`voicegram-generation-v1` 사이트 저장소에 생성 요청을 `onlyIfNew`로 먼저 기록하고, 성공한 요청만 외부 제공자에게 전달한다. 같은 요청 번호의 재전송은 저장된 결과 또는 처리 중 상태를 반환한다. 프롬프트·종류·비율·참조 이미지가 달라지면 같은 번호 재사용은 거절한다.

소유 범위는 서명된 테스트 세션의 nonce를 해시한 값이다. 다른 세션에서는 결과를 조회할 수 없다. 조회 가능 시간은 해당 세션 만료 또는 8시간 중 빠른 시점까지다. 실제 결과 저장에 실패하거나 제공자 결과가 불확실한 경우 기존 요청을 자동 재실행하지 않는다.

`generation-cleanup`은 만료된 생성 임시 결과만 정리하도록 매일 04:00 UTC (한국 13:00)에 설정한다. 회당 최대 500개/20초 범위로 처리한다. 게시물 저장소와 사용자 기기 초안은 정리 대상이 아니다. 배포 직후에는 스케줄의 실제 첫 실행을 확인했다고 간주하지 않는다.

기기 저장은 브라우저 정책/사용자 데이터 삭제/저장 공간 부족의 영향을 받을 수 있으므로 ‘영구 보관’으로 안내하지 않는다. 주요 완성 파일은 파일 저장 기능을 통해 내려받을 수 있다.

## 검증

- TypeScript + `node --test tests/*.test.mjs`: 17개 테스트.
- `tests/browser-creation.mjs`: 실제 `studio`, `social`, `chat` 핸들러와 브라우저 화면을 연결. 외부 AI 제공자와 Netlify 저장소만 테스트 대역 사용.
- 생성 확인, 참조 사진 수정 요청, 이전 그림 복원, 글/이미지 새로고침 복구, 게시 성공 응답 유실 후 동일 게시물 유지, 생성 성공 응답 유실 후 읽기 전용 결과 복구, 제공자 실패 시 이전 그림 유지, 로컬 6초 영상 생성/Blob 복구 검증.

- 모의 제공자 호출 4회 중 참조 이미지 편집 1회, 게시 요청 2회(응답 유실 재시도 포함)에 최종 게시물 1개. 유료 API 호출과 실제 사용자 게시물 생성은 없음.
